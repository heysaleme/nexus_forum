# Nexus Forum

Reddit-подобная веб-платформа для публикации контента, обсуждений, сообществ и real-time чатов. 

Проект построен на современном стеке технологий с разделением на независимый Go-бэкенд (Clean Architecture) и React/Vite-фронтенд.

---

## 🚀 Как запустить

Вы можете запустить проект двумя способами: через Docker Compose или вручную.

### Вариант А: Через Docker Compose (Рекомендуемый)
Убедитесь, что у вас установлен Docker и запущен Docker Desktop.

1. Запустите контейнеры из корневой директории проекта:
   ```bash
   docker compose up --build
   ```
2. Откройте в браузере: **`http://localhost:5173`**
3. База данных SQLite автоматически создастся и наполнится демонстрационными данными. База данных сохраняется в файле `./backend/nexus_forum.db` на хосте.

### Вариант Б: Ручной запуск
Если вы хотите запустить проект без Docker:

1. **Запуск Бэкенда (Go):**
   ```bash
   cd backend
   go run ./cmd/api
   ```
   *Сервер запустится на порту `8080`.*

2. **Запуск Фронтенда (React/Vite):**
   В новом окне терминала в корне проекта:
   ```bash
   npm install
   npm run dev
   ```
   *Фронтенд запустится по адресу `http://localhost:5173` (или другом свободном порту, указанном Vite).*

## 🏗️ Архитектура бэкенда (Clean Architecture)

Бэкенд-код в директории `backend/internal` строго следует правилам чистой архитектуры и разбит на изолированные слои:

1. **Model (`internal/model/`)** — Чистые структуры данных GORM (сущности пользователей, сообществ, постов, комментариев, логов и аналитики).
2. **DTO (`internal/dto/`)** — Объекты передачи данных для валидации входящих HTTP-запросов и форматирования JSON.
3. **Repository (`internal/repository/`)** — Слой взаимодействия с базой данных (GORM + SQLite/Postgres). Каждая сущность имеет собственный изолированный файл репозитория.
4. **Service (`internal/service/`)** — Слой бизнес-логики (авторизация с шифрованием bcrypt/JWT, начисление XP/уровней, валидация прав доступа, бизнес-правила).
5. **Handler (`internal/handler/`)** — Слой контроллеров Gin, преобразующих HTTP/WebSocket запросы в вызовы служб бизнес-логики.
6. **Middleware (`internal/middleware/`)** — Logger на базе структурированного `slog` и авторизация по токенам JWT Bearer.

## 📊 Модули и ТЗ-аудит

- **Модуль аутентификации:** Регистрация, авторизация через JWT, OTP-подтверждение (`123456`), настройки приватности, редактирование аватара и баннера.
- **Модуль сообществ:** Создание, вступление/выход, отображение правил, аватаров и баннеров. Поддерживаются публичные, приватные и NSFW типы.
- **Модуль постов:** Поддержка типов (Текст, Изображение, Ссылка, Опрос). Сортировка по Hot (Reddit-подобный рейтинг), New, Top. Сохранение в закладки, черновики.
- **Модуль комментариев:** Древовидная (nested) структура комментариев с возможностью сворачивания веток, голосованием и авто-уведомлением автора.
- **Модуль голосования:** Рейтинговая система (+1 / -1) для постов и комментариев с авто-пересчетом XP пользователя (вместо кармы).
- **Модуль сообщений (чат):** Real-time чат с поддержкой WebSocket (авторизация по токенам в URL), сохранением истории сообщений в БД и индикацией прочтения.
- **Модуль модерации:** Возможность блокировки (бан/разбан) пользователей, удаления неуместного контента (постов/комментариев) с автоматическим ведением истории аудита модерации (`ModerationLog`).
- **Модуль аналитики:** Dashboard для администратора, отображающий DAU/MAU, число постов, просмотров и график роста пользователей за 30 дней.
